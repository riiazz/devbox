# v1.1.0 — Live Dashboard and Service Management

DevBox is a reproducible development environment tool written in Rust. It owns
the development environment — not the operating system — and integrates with
existing tools instead of replacing them.

v1.1.0 turns `devbox up` into something you want to keep on screen: a live
dashboard that shows every service's status, CPU, memory, and ports alongside
its logs — and a full set of commands to manage services from the CLI.

## Highlights

- **Live `devbox up` dashboard** — redrawn every second, showing each
  service's status, PID, parent PID, current CPU usage, memory, listening
  ports, and live logs. Logs default to the first five services (last five
  lines each); `--service <name>` (repeatable) picks services to follow and
  `--log-lines <n>` controls log depth. Ctrl+C stops the services and clears
  the supervisor state.
- **`devbox services`** — manage services from the CLI: `add` new ones (with
  an optional external `env_file`), `enable`/`disable` whether `devbox up`
  starts them, and `list` the whole `[services]` section.
- **`devbox config <name>`** — inspect a service's resolved configuration from
  `devbox.toml`, including its external `env_file` environment.
- **`devbox clear-logs`** — truncate service log files without deleting them.
- **External environment configuration** — a service can load its environment
  from a separate TOML file via `env_file`, handy for ASP.NET-style
  `ConnectionStrings__*` and `Logging__*` variables.
- **Safe `devbox stop`** — only PIDs still verified to be children of the
  devbox process that spawned them are terminated; a reused PID is left alone
  and pruned from the state file.
- **Custom GitHub asset templates** — `devbox install` can resolve tools that
  don't follow the default `<name>-<version>-<triple>.<ext>` naming, via
  `asset` templates with `{name}`, `{version}`, `{version_v}`, `{os}`,
  `{arch}`, `{triple}`, and `{ext}` placeholders.

## Commands

| Command | Description |
|---------|-------------|
| `devbox init` | Create the `.devbox/` workspace and a starter `devbox.toml` |
| `devbox exec <program> [args...]` | Run a program inside the DevBox environment |
| `devbox shell` | Open an interactive shell inside the environment |
| `devbox install <name> [--version <v>]` | Download and register a tool |
| `devbox tools list` / `devbox tools register` | Manage the tool registry |
| `devbox up [--service <name>...] [--log-lines <n>]` | Start and supervise `[services]` with a live dashboard |
| `devbox status` | Report service PIDs and status |
| `devbox logs [name] [--lines <n>]` | Print service logs |
| `devbox clear-logs [name...]` | Truncate service log files |
| `devbox stop [name...]` | Stop supervised services |
| `devbox services add <name> <command> [args...] [--env-file]` | Add a service to `devbox.toml` |
| `devbox services enable <name>` | Let `devbox up` start a service |
| `devbox services disable <name>` | Make `devbox up` skip a service |
| `devbox services list` | List services from `devbox.toml` |
| `devbox config <name>` | Print a service's resolved configuration |

## Dashboard

`devbox up` supervises the enabled services in the foreground and redraws a
live dashboard once a second:

    devbox running with pid: 3333

    | service    | status  | pid  | parent_pid | cpu | memory | listening      |
    | ---------- | ------- | ---- | ---------- | --- | ------ | -------------- |
    | caddy      | running | 1100 | 3333       | 3%  | 2kb    | localhost:2009 |
    | rbac       | running | 1231 | 3333       | 5%  | 3mb    | localhost:4041 |
    | rbac-child | running | 1235 | 1231       |     |        |                |

    logs:
    ---
    service: caddy
    ...

Ctrl+C — or closing the terminal — interrupts the dashboard, stops the
supervised services, and clears the supervisor state.

## Service management

Declare `[services]` in `devbox.toml` and manage them from the CLI:

    devbox services add coredns coredns -conf Corefile

    devbox services disable caddy
    devbox services enable caddy

    devbox services list

Services can be marked `enabled = false` so `devbox up` keeps them defined but
skips starting them.

## External environment files

A service can load its environment from a separate TOML file instead of
inlining it in `devbox.toml`:

```toml
[services.contract-oncall]
command = "dotnet"
args = ["run"]
cwd = "C:/repos/contract-oncall"
env_file = "./.devbox/workspace/configs/contract-oncall.toml"
```

The file holds an `[environment]` table, whose values are injected into the
service process. Inline `[services.<name>.environment]` values override
`env_file`. `devbox config <name>` prints the merged result.

## Fixed

- **Bouncing shell prompt** — `devbox exec` and `devbox shell` no longer
  orphan a child shell when Ctrl+C is pressed.
- **Logs unavailable** — `devbox logs` reads the log files directly from the
  workspace, so logs are available even when the supervisor state is stale.
- **Port listing** — the dashboard now lists ports opened by descendant
  processes, not just direct children.
- **Dashboard log panel** — the dashboard no longer redraws a blank log panel.

## Supported platforms

- Windows (PowerShell)
- Linux (bash)
- macOS (bash)

## Installing

```text
cargo install --path crates/cli --locked
```

Then, in any project:

```text
devbox init
devbox install ripgrep
devbox shell
```
